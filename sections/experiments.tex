\section{Experiments}
\label{sec:experiments}

\subsection{Evaluation Protocol}

We evaluate 39 RGB-D loop-closure cases from 18 Kimera-Multi
sequences~\cite{tian23arxiv_kimeramultiexperiments} and 12 LiDAR cases from
six KITTI sequences~\cite{Geiger2013IJRR}, each bag is ran by Orbslam3 once and record the loop closure it creates. Every method reconstructs the same
temporal interval. For Kimera-Multi, the reference geometry is the official ground-truth point cloud, cropped to a 5 m tube around the
corresponding official trajectory to match Voxblox's maximum integration
range. For KITTI, the reference is the GT-registered point cloud within the
mapper's 25 m ray range. Estimated-trajectory use RANSAC--Umeyama $\mathrm{Sim}(3)$ only to best align GT-trajectory positions; no mesh-to-GT registration is used. Reconstructions
built from the same corrected trajectory share one transform per case.
Voxgraph is aligned from its own reported trajectory because it maintains an
independently optimized submap frame; this baseline-specific trajectory fit
cannot improve WarpVox relative to Voxgraph.

WarpVox runs alongside the standard Voxblox fusion pipeline, automatically extracting and caching the modality-native range image of each required SLAM keyframe as it arrives. Thus, no bag rewind or separate keyframe-image preprocessing is required at loop events. At every loop event, WarpVox
re-associates the current source surface against the eligible cached keyframes,
executes Stages~2--4, replaces the active Voxblox TSDF, discards the derived
event state, and resumes fusion from the next frame. For the eighteen RGB-D
sequences, the cache holds one uncompressed 16-bit depth image per keyframe at
$0.646\,\mathrm{MiB}$, giving $0.9$--$3.6\,\mathrm{GiB}$ over 1349--5707
keyframes (mean $2.1\,\mathrm{GiB}$). Voxblox reintegration interpolates the same SLAM keyframes to replay all frames, whereas WarpVox uses only the keyframe.

\noindent\textbf{Baselines.}
Uncorrected voxblox TSDF uses the pre-correction trajectory.
Open3D~\cite{zhou2018open3dmodernlibrary3d} is an independent corrected-pose
TSDF rebuild;
Wavemap~\cite{reijgwart2023wavemap} rebuilds a wavelet occupancy map, and
Voxgraph~\cite{reijgwart2020voxgraph} optimizes rigid TSDF submaps. Voxblox
reintegration~\cite{Oleynikova_2017} is therefore the representation-matched
reference. WarpVox instead uses the active uncorrected TSDF.

We compute precision and recall by bidirectional nearest-neighbour tests and
report F@10/25/50 at 0.10/0.25/0.50 m. All methods share each case's crop,
spatial region, two-million-point sample, random seed, and thresholds. Main
TSDF experiments use 0.25 m voxels and 1.0 m truncation; Wavemap uses a matched
0.25 m finest level. Core algorithm runtimes are measured from in-memory map state on an AMD Ryzen 7 9700X with 64 GB RAM, excluding I/O, serialization, and evaluation-only mesh extraction for all methods.
WarpVox uses Voxblox’s online mesh, excluding keyframe caching. PGMO excludes MeshFrontend construction, while both PGMO and Voxgraph report backend time between consecutive loop events.
Supplementary code contains all implementation,
evaluation, and cases configurations scripts.

\noindent\textbf{Source-volume semantics.}
For the fields defined in
\eqref{eq:hybrid_tsdf}--\eqref{eq:hybrid_weight}, we compare WarpVox with
corrected-pose Voxblox reintegration on 10 0.25 m cases. Over voxels
with positive weight in both maps and within the reference truncation band,
the truncation-normalized TSDF MAE
$\mathbb E[|\Phi^+-\Phi_{\rm reint}|]/\tau$ is 0.384, where
$\Phi_{\rm reint}$ denotes the reintegrated reference field; sign agreement is
$95.17\%$. Treating $w>0$ as observed, support precision, recall, and IoU are
$95.53\%$, $68.38\%$, and $66.33\%$, respectively. Thus, WarpVox
conservatively preserves observed-space semantics, introducing little
unsupported space but retaining less support than full reintegration.

\subsection{Event-Triggered Comparison with Kimera-PGMO}
\label{sec:pgmo}

Kimera-PGMO continuously updates a joint pose--mesh deformation graph, whereas
WarpVox is triggered by a global trajectory revision.
Table~\ref{tab:pgmo_full10} compares final states on ten complete Kimera-Multi
bags using the same 5 cm Kimera uncorrected-mesh and final VIO-to-PGMO correction.
PGMO additionally exploits timestamped pose--mesh and mesh--mesh associations;
WarpVox constructs observation controls from cached keyframe range images and
VIO poses. When asynchronous replays vary, we select the complete
trajectory--mesh pair with lowest ATE, independently of mesh accuracy, and
apply its correction to both methods. Because the native pre-mesh has no source
TSDF, WarpVox uses mesh-only Stage~4; this comparison therefore tests surface
correction, not source-support transfer.

One WarpVox update improves mean F@25/F@50 by 1.24/3.03 pp (median F@50
difference 0.20 pp) while using 47.02 s versus PGMO's 435.97 s accumulated over
all callbacks. Per-bag F@50 differences form two groups: four gains of
5.5--11.7 pp and six cases within $\pm0.5$ pp; two of the latter are marginally
negative. The two negative cases exhibit opposite precision--recall tradeoffs:
one gains 6.51 pp recall while losing 3.26 pp precision, whereas the other gains
1.41 pp precision while losing 0.92 pp recall. Thus WarpVox offers a lower-cost
final-state operating point, while PGMO provides intermediate updates and
temporal mesh associations.

\subsection{Extension to Gaussian Primitives}

To test representation transfer, we apply the same targets to a
SplaTAM~\cite{keetha2024splatam} map while changing only Gaussian centres.
On one sequence, F@25/F@50 rises from 17.23/35.25 to 23.12/40.59 and depth L1
falls from 173.93 to 142.54 cm in about 21 s; a corrected-pose rebuild obtains
23.25/41.01 and 141.37 cm in about 2 h. PSNR/MS-SSIM/LPIPS improve from
11.96/0.512/0.430 to 12.59/0.526/0.411. This isolates the target mechanism:
Gaussian splats~\cite{kerbl2023gaussians} still lack the signed-distance and
observed-free-space semantics that keep TSDF/ESDF mapping as WarpVox's primary
robotics setting.

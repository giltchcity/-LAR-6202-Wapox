\section{Experiments}
\label{sec:experiments}

\subsection{Evaluation Protocol}

We evaluate 39 RGB-D loop-closure cases from 18 Kimera-Multi
sequences~\cite{tian23arxiv_kimeramultiexperiments} and 12 LiDAR cases from
six KITTI sequences~\cite{Geiger2013IJRR}. Each bag is run through ORB-SLAM3 once, and all loop-closure events it produces
are recorded. Every method reconstructs the same
temporal interval. For Kimera-Multi, the reference geometry is the official ground-truth point cloud, cropped to a 5 m tube around the
corresponding official trajectory to match Voxblox's maximum integration
range. For KITTI, the reference is the GT-registered point cloud within the
mapper's 25 m ray range. Predictions expressed outside the GT frame are aligned by a RANSAC--Umeyama 
% $\mathrm{Sim}(3)$ 
fitted only to timestamp-matched trajectory positions; no
mesh-to-GT registration is used. Reconstructions
built from the same corrected trajectory share one transform per case.
Voxgraph is aligned from its own reported trajectory because it maintains an
independently optimized submap frame; this baseline-specific trajectory fit
cannot improve WarpVox relative to Voxgraph.

WarpVox runs alongside the standard Voxblox fusion pipeline, automatically extracting and caching the modality-native range image of each required SLAM keyframe as it arrives. Thus, no bag rewind or separate keyframe-image preprocessing is required at loop events. At every loop event, WarpVox
re-associates the current source surface with the cached keyframes,
executes Stages~2--4, replaces the active Voxblox TSDF, discards the derived
event state, and resumes fusion from the next frame. For the eighteen RGB-D
sequences, the cache holds one uncompressed 16-bit depth image per keyframe at
$0.646\,\mathrm{MiB}$, giving $0.9$--$3.6\,\mathrm{GiB}$ over 1349--5707
keyframes (mean $2.1\,\mathrm{GiB}$). 


\noindent\textbf{Baselines.}
Uncorrected Voxblox TSDF uses the pre-correction trajectory.
Open3D~\cite{zhou2018open3dmodernlibrary3d} is an independent corrected-pose
TSDF rebuild;
Wavemap~\cite{reijgwart2023wavemap} rebuilds a wavelet occupancy map, and
Voxgraph~\cite{reijgwart2020voxgraph} optimizes rigid TSDF submaps. Voxblox
reintegration~\cite{Oleynikova_2017} is therefore the representation-matched
reference. WarpVox instead uses the active uncorrected TSDF.

At each loop event, WarpVox, Voxblox reintegration, Open3D, and Wavemap
receive the same corrected keyframe trajectory; Voxgraph retains its
independently optimized submap frame as described above. For the
representation-matched reference, Voxblox interpolates this trajectory to
every range-frame timestamp in the reconstructed interval and re-fuses the
complete range stream. WarpVox instead uses the keyframe range measurements
only to construct correction targets; it does not volumetrically re-fuse them.

We compute precision and recall by bidirectional nearest-neighbour tests and
report F@10/25/50 at 0.10/0.25/0.50 m. All methods share each case's crop,
spatial region, two-million-point sample, random seed, and thresholds. Main
TSDF experiments use 0.25 m voxels and 1.0 m truncation; Wavemap uses a matched
0.25 m finest level.

\noindent\textbf{Timing protocol.}
For all methods, we report core map-update time from in-memory state on an AMD Ryzen 7 9700X with 64\,GB RAM: TSDF/occupancy integration, submap or mesh optimization, or WarpVox source-mesh-to-TSDF correction, as applicable. Disk I/O, mesh extraction, and processing outside correction, including PGMO MeshFrontend construction, are excluded.

\label{sec:pgmo}

That pre-mesh carries no source TSDF, so WarpVox uses mesh-only Stage~4: this experiment compares surface correction alone.

\noindent\textbf{Stage-4 source-volume semantics.}
For the fields defined in \eqref{eq:hybrid_tsdf}--\eqref{eq:hybrid_weight}, we compare WarpVox with corrected-pose Voxblox reintegration on the same ten cases. Over voxels with positive weight in both maps and within the reintegrated truncation band, the truncation-normalized absolute field difference $\mathbb E[|\Phi^+-\Phi_{\rm reint}|]/\tau$ is 0.384, with $95.17\%$ sign agreement. The field difference is not purely a geometric error: WarpVox uses Euclidean distance to the warped surface, whereas Voxblox integrates projective ray distances, which need not coincide away from the same zero set~\cite{han2018flashfusion}. We therefore assess zero-set consistency using the surface F-scores above and sidedness using sign agreement. Treating $w>0$ as observed, support precision, recall, and IoU are $95.53\%$, $68.38\%$, and $66.33\%$, respectively. WarpVox thus introduces little unsupported space, although it retains less observed support than full reintegration.



Varying the per-vertex association cap $n_v \in \{1,4,8,15\}$ on the same ten cases changes mean F@25 by only $0.019$ pp, with a maximum per-checkpoint range of $0.085$ pp. At $n_v=15$, vertices retain only $2.91$ records on average and $1.90\%$ reach the cap; we therefore use $n_v=15$ to avoid truncating valid support while keeping per-vertex storage bounded.



\noindent\textbf{Cross-representation 3DGS case study.}
To test whether the observation-derived target mechanism transfers beyond TSDFs, we apply the same corrected surface targets to the Gaussian centres of one Kimera-Multi sequence reconstructed with SplaTAM~\cite{keetha2024splatam}, while leaving all other Gaussian attributes unchanged. F@25/F@50 improves from 17.23/35.25 to 23.12/40.59, and depth L1 decreases from 173.93 to 142.54 cm in 21 s. A corrected-pose rebuild obtains 23.25/41.01 and 141.37 cm in approximately 2 h. This single-sequence result suggests that the target construction can transfer beyond voxel grids. It is reported only as a representation-transfer case study: Gaussian splats~\cite{kerbl2023gaussians} do not provide the signed-distance and observed-free-space semantics targeted by WarpVox's primary TSDF mapping setting.
